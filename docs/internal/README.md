## 1. 项目定位

参加 Cognizant 的 **Open Agentic Web Challenge**，提交一个真实可运行的开放智能体网站：**Agent Network Board（智能体网络看板）**。

核心设想是把开放智能体网络的关键过程可视化、可验证：

- **真实发现**：从公开 `agent-manifest.json` 和网络定义中读取其他站点实际发布的智能体与能力，不使用写死的假智能体列表。
- **能力声明**：展示每个 agent 的名称、职责、输入 JSON Schema、可调用工具和对等网络 URL。
- **任务交接**：由真实 browser runtime 在 agent 之间委派任务，并在用户同意后调用另一个已发布的 agent network。
- **信任证据**：只显示可核验的检查结果（HTTPS、manifest 精确匹配、CORS、front agent 是否存在、实际访问来源、工件哈希等），不编造信誉分。
- **审计界面**：时间线直接来自 runtime 的真实事件——路由选择、来源访问、工具调用、同意决定、错误与回执；不记录密钥。

这是新项目，不是 GhostBBS 的模拟 agent 或换皮版本。允许复用公开、可许可的通用架构经验，但提交物必须是本参赛者原创、独立且实质上不同的作品。

## 3. 必须交付

最终 Devpost 提交需要：

1. 可公开访问的 HTTPS 智能体网站。
2. 可公开访问、符合规范的 agent-network JSON。
3. 能在浏览器中运行该网络的 runtime。
4. 供用户或 agent 与网络交互的界面。
5. 可选的 LLM/密钥配置界面；若站点没有默认推理路径，则实际需要 BYOK 配置。
6. 文本说明、至少一张网站截图。
7. **少于 2 分钟**的 YouTube 公开演示视频：显示浏览器中的真实运行、由参赛者本人讲解、不得是 AI 生成讲解；未经许可不得使用第三方商标或受版权保护素材。
8. 如果使用 Mozilla Otari：提供账户邮箱，并简述遇到的问题及改进建议。
9. 非英文材料需提供英文翻译；Devpost 提交文案与视频说明应以英文准备。

规范层面还应发布 `agent-manifest.json`、解析后的网络定义和 `links.json`，并为跨源公共工件配置 CORS。
